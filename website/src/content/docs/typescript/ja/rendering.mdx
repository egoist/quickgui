コンポーネントはマウント時に実行され、表示すべきツリーを返します。その後のシグナル更新は、バインドされたテキストとプロパティを変更します。子構造そのものが変わるときは `<Show>` と `<For>` を使います。

## レンダリングモデル

コンポーネントからネイティブ JSX を返します。レイアウト、描画、フォーカス、アクセシビリティはネイティブです。HTML には描画しません。

```tsx
<View padding={20} gap={12}>
  <Text>Hello</Text>
  <Button onClick={() => {}}>Continue</Button>
</View>
```

## 条件付きコンテンツ

セットアップ中の普通の `if` は、コンポーネント作成中にだけ実行されます。子をあとから出したり消したりするときは `<Show>` を使います。

```tsx
<Show when={expanded()} fallback={<Text>Collapsed</Text>}>
  <Text>Expanded content</Text>
</Show>
```

分岐を外すと、そのエフェクトとノードが解放されます。兄弟ノードの同一性は保たれます。

## リストとノードの同一性

```tsx
<For each={items()}>{(item) => <Text>{item.name}</Text>}</For>
```

状態を持つ行には位置ではなく、id などの安定した同一性を与えます。並べ替えると既存の行が移動します。大きな集合では `Table` や `Tree` を使い、見える行だけをマウントします。

## ウィンドウのライフサイクル

各 `Window` は独自の Solid ルートを持ちます。1 つのウィンドウを閉じても兄弟は破棄されません。macOS では、Dock の再オープンが `hasVisibleWindows` が false だと報告したときに新しいウィンドウを開きます。

## 現在のウィンドウ

```tsx
function Content() {
  const window = Window.getCurrentWindow();
  return <Button onClick={() => window.close()}>Close</Button>;
}
```

セットアップ中にウィンドウを保持するか、あとの非同期処理へ渡してください。

## チェック・テスト・デバッグ

```sh
bun run check
bun run test
```

`check` はアプリと同じ JSX 変換で型検査します。`test` はアプリケーションテストを実行します。
