## 配置

Install the updater extension in your application:

```sh
bun add @quickgui/extension-updater
```

Generate the update-signing keys, then copy the public key into your project:

```sh
bunx @quickgui/cli keygen --sparkle --out-dir "$HOME/.config/my-app/update-keys"
cp "$HOME/.config/my-app/update-keys/quickgui-update.pub" ./update-public-key.pub
```

Keep the private `quickgui-update.key` outside version control. The public `update-public-key.pub` file belongs with your application source.

Use this complete `quickgui.config.ts`, replacing the application metadata and download URL:

```ts
import { readFileSync } from "node:fs";
import { defineConfig } from "@quickgui/cli";

export default defineConfig({
  language: "typescript",
  name: "My App",
  identifier: "com.example.my-app",
  version: "1.0.0",
  entry: "app.tsx",
  extensions: ["@quickgui/extension-updater"],
  updates: {
    baseUrl: "https://downloads.example.com/my-app",
    publicKey: readFileSync(
      new URL("./update-public-key.pub", import.meta.url),
      "utf8",
    ).trim(),
    automaticChecks: true,
  },
});
```

The CLI embeds the public key, application version, identifier, and feed URL in the application. With this configuration, a `darwin-arm64` build checks `https://downloads.example.com/my-app/appcast-darwin-arm64.xml`. Set `updates.feedUrl` to override that default; it can contain `{target}`.

Production applications require the public-key configuration. The private key is needed when signing release artifacts with `--update-manifest`, and is never embedded in the application.

## 应用用法

Create `updates.ts` and import it once from your application's `app.tsx`. Start the updater after application readiness, outside components, so every window shares one session:

```ts
import { app } from "@quickgui/native";
import Updater from "@quickgui/extension-updater";

await app.whenReady();

export const updater = new Updater({}, event => {
  if (event.error) console.error(event.error);

  if (event.quitRequired) {
    // The installer is ready; normal quit hooks can save work or cancel quitting.
    void app.quit().catch(console.error);
  }
});

await updater.ready;
```

The empty options object uses the settings embedded from `quickgui.config.ts`. A Check for Updates action can use that shared instance:

```tsx
import { Button } from "@quickgui/solid";
import { updater } from "./updates";

export function CheckForUpdatesButton() {
  return (
    <Button p-3 rounded-lg onClick={() => {
      void updater.check().catch(console.error);
    }}>
      Check for Updates
    </Button>
  );
}
```

## 生命周期

`updater.ready` rejects if initialization fails. Commands return promises; handle their errors at the action that invokes them.

| API | Use |
| --- | --- |
| `updater.check()` | Manually check for an update. |
| `updater.install()` | Install an available update from your update banner. |
| `updater.setAutomaticChecks(enabled)` | Change the automatic-check preference from settings. |
| `updater.state` | Read the last native event without polling. |
| `updater.close()` | Stop a session that the application no longer needs. |

The callback receives status, version, notes, progress, and errors. Status is `idle`, `checking`, `available`, `downloading`, `installing`, or `disabled`. Import `UpdateEvent` and `UpdaterOptions` types from `@quickgui/extension-updater` when needed.

Closing a window must not close the shared updater. Native sessions are cleaned up when the application quits.

Development builds report `disabled` by default. To test against a deliberately configured test feed and disposable app bundle, replace the options object with `{ allowDevelopment: true }`. On macOS, the supplied public key must match the key embedded in the app bundle.

## 平台支持

The extension uses Sparkle on macOS. Windows and Linux have native implementations for signed NSIS installers and AppImages respectively; the current npm artifacts cover macOS, so other targets require extension builds on their target hosts. Linux package-manager installations report `disabled`.

The native extension owns download verification, installation, and relaunch. The TypeScript API sends commands and receives events through the existing in-process extension bridge.

## 发布更新

Increase `version` in `quickgui.config.ts` for each release. Load the private signing key into the build environment:

```sh
export QUICKGUI_UPDATER_PRIVATE_KEY="$(cat "$HOME/.config/my-app/update-keys/quickgui-update.key")"
```

For a macOS release, use your Developer ID signing identity and configured notary profile:

```sh
bunx @quickgui/cli build --target darwin-arm64 --update-manifest \
  --sign "Developer ID Application: Example (TEAMID)" \
  --notarize my-app-notary
```

The CLI signs the finished update archive and writes `appcast-darwin-arm64.xml`. Upload the versioned archive to the directory configured by `updates.baseUrl` first, then upload the appcast to its feed URL. The CLI reports the artifact and appcast paths. Repeat with `--target darwin-x64` for Intel Macs; each architecture uses its own feed.

For CI, provide `QUICKGUI_UPDATER_PRIVATE_KEY` through the CI secret store and keep the public-key file in the checkout. `SPARKLE_PRIVATE_KEY` is also accepted. For local signing, `updates.ed25519SecretKey` can point to the private key file instead of using an environment variable. Set `updates.manifest: true` to generate a signed appcast on every production build, or `updates.notesFile` to include a release-notes text file.

The private key must match `updates.publicKey`. Missing keys, mismatched keys, and unsupported update payloads fail the release build.

## 原生产物

```sh
bun packages/native/build.ts --extension updater
```

In a source checkout, build the extension once. Packaged applications include its shared library, Sparkle resources or portable handoff helper, and the update metadata selected by the CLI.
