导入 `github.com/egoist/quickgui/go/updater` 即可启用自动更新。未导入该包的应用不会包含更新器。

## 配置

生成一对 Ed25519 密钥：

```sh
bunx @quickgui/cli keygen --sparkle --out-dir /secure/my-app-update-keys
```

不要将私钥 `.key` 提交到版本控制。将 `.pub` 文件的内容复制到 `quickgui.toml`：

```toml
[updates]
baseUrl = "https://downloads.example.com/my-app"
publicKey = "BASE64_PUBLIC_KEY_FROM_THE_PUB_FILE"
automaticChecks = true
# Optional; {target} expands to darwin-arm64, windows-x64, and so on.
feedUrl = "https://downloads.example.com/my-app/appcast-{target}.xml"
# Optional release notes, at most 16 KiB of plain text.
notesFile = "RELEASE_NOTES.md"
```

CLI 会将版本、标识符、feed URL 和公钥嵌入应用。私钥永远不会被嵌入。

Developer ID 应用受支持。App Store 和沙盒构建应通过 Go build tag 或平台专用文件省略 updater 导入。

## 应用用法

在 `native.Run` 就绪之后、组件之外启动更新器。在设置、菜单和更新横幅之间共享同一个句柄。关闭窗口不得关闭更新器。

```go
import (
	"log"

	"github.com/egoist/quickgui/go/native"
	"github.com/egoist/quickgui/go/updater"
)

var updates *updater.Updater

func startUpdater() {
	updates = updater.Start(updater.Options{}, func(event updater.Event) {
		if event.Error != "" {
			log.Print(event.Error)
		}
		if event.QuitRequired {
			native.App.Quit(false, nil)
		}
	}, func(err error) {
		if err != nil {
			log.Print(err)
		}
	})
}
```

从「检查更新」菜单项调用 `updates.Check(done)`，从可用更新横幅调用 `updates.Install(done)`，从设置调用 `updates.SetAutomaticChecks(enabled, done)`。回调在 UI goroutine 上运行。`State()` 返回最近一次事件。

`Options` 可以覆盖 feed URL 和公钥。开发构建会保持禁用，除非你对测试 feed 和可丢弃的应用包设置 `AllowDevelopment: true`。

## 生命周期

`Event.Status` 为 `idle`、`checking`、`available`、`downloading`、`installing` 或 `disabled`。事件包含版本、说明、进度、自动检查偏好，以及可选错误。

在 macOS 上，Sparkle 负责下载、验证、安装和重新启动。定时检查的结果可用于应用内横幅；手动检查可以显示 Sparkle 的标准窗口。

在 Windows 和 Linux 上，启用自动检查时每次启动检查一次。`QuitRequired` 表示安装程序已就绪：处理完未保存的工作后调用 `native.App.Quit(false, nil)`。如果退出被取消，辅助程序会等待两分钟，并保持正在运行的应用不变。

## 平台支持

| 平台 | 更新包 | 安装方式 |
| --- | --- |
| macOS | 包含已签名 `.app` 的 ZIP | Sparkle |
| Windows | QuickGUI NSIS `.exe` 安装程序 | 辅助程序等待退出后静默运行安装程序，然后重新启动 |
| Linux | Type-2 `.AppImage` | 辅助程序等待退出后替换用户拥有的 AppImage |

Linux 的 `.deb` 软件包、系统二进制文件以及 root 拥有的安装会报告 `disabled`；请改用包管理器。

这些 feed 是带 Ed25519 签名的 HTTPS Sparkle appcast。每个架构有独立的 feed。不会生成增量包或分阶段发布。

## 发布更新

将私钥放在 `QUICKGUI_UPDATER_PRIVATE_KEY`（或 `SPARKLE_PRIVATE_KEY`）中。本地签名时，`updates.ed25519SecretKey` 可以指向密钥文件。

```sh
bunx @quickgui/cli build --update-manifest
```

CLI 会签署平台产物并写入 `appcast-<target>.xml`。先上传带版本号的产物，再替换其 HTTPS URL 上的 feed。`updates.manifest = true` 会在每次生产构建时生成 feed。

macOS 归档应包含 Developer ID 签名并已公证的应用。Windows 需要 `makensis`。Linux 需要 `appimagetool` 才能生成可更新的 AppImage。

参见[更新器示例](https://github.com/egoist/quickgui/tree/main/examples/updater)和 [Sparkle 文档](https://sparkle-project.org/documentation/)。

## 原生产物

生产构建在应用导入该包时已经包含更新器。最终用户运行打包后的应用，无需安装额外的更新器工具。
