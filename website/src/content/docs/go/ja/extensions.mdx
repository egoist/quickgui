UI は Go パッケージとして共有できます。QuickGUI が同梱していない追加ライブラリが必要なときは、ネイティブサービスを追加します。

## 拡張の種類を選ぶ

| 追加するもの | 配布するもの |
| --- | --- |
| コンポーネント、テーマ、ヘルパー | Go モジュール |
| ネイティブサービスまたは SDK | Go パッケージとネイティブライブラリ |
| そのサービスを使う UI | 両方（サービスとコンポーネント） |

既存の API で足りる場合は Go パッケージから始めてください。独自 SDK のようなものが必要なときはネイティブ拡張を追加します。[自動更新](/docs/go/updater) は後者の例です。

利用者は Go パッケージをインポートします。CLI はマニフェストを見つけ、対応するネイティブライブラリを同梱します。

## 拡張プロジェクトを作成する

```sh
bunx @quickgui/cli init-extension my-components --type go
bunx @quickgui/cli init-extension my-service --type zig
bunx @quickgui/cli init-extension my-service --type rust
```

`--type go`（既定）は再利用可能なコンポーネントの雛形を作ります。`zig` と `rust` は Go ラッパーとデモアプリ付きのネイティブサービスの雛形を作ります。

```sh
cd my-service
bun run dev
```

Go モジュールパスには `--module github.com/acme/my-service`、ネイティブパッケージには `--npm-package @acme/extension-my-service` を使います。`--name` はディレクトリから導出したサービス名を上書きします。

`bun run build` は現在のマシン向けネイティブライブラリを `artifacts/lib/<target>/` にコンパイルします。`bun run dev` は一度ビルドしたあと、Go の編集をリロードします。ネイティブコードを変更したあとは再起動してください。純粋な Go 拡張はネイティブビルドをスキップします。

## コンポーネントの共有

QuickGUI の Go モジュールに依存し、コンポーネント関数をエクスポートします。

```go
package notice

import "github.com/egoist/quickgui/go/ui"

func Notice(message func() string, styles ...ui.StyleBuilder) *ui.Element {
	return ui.Text(message()).
		Padding(12).
		BackgroundColor("#eff6ff").
		TextColor("#1e40af").
		BorderRadius(8).
		Style(ui.Style().Merge(styles...))
}
```

`notice.Notice(message, ui.Style().Padding(16))` を呼び出すか、結果を子として渡します。モジュールは Go のバージョンタグで公開します。利用者は `go get` で追加します。

任意のネイティブ連携は別パッケージに分け、UI だけ欲しいアプリが引き込まないようにします。マウントされたコンポーネントが所有するリソースには `ui.OnCleanup` を使います。

## ネイティブ拡張の構成

Go パッケージと小さなネイティブライブラリを対にします。[`native-extension` の例](https://github.com/egoist/quickgui/tree/main/examples/native-extension) がこの構成を示します。

```text
go.mod
echo/
  echo.go
  quickgui.extension.json
native/
  echo.c
artifacts/
  package.json
  lib/darwin-arm64/libquickgui_acme_echo.dylib
```

後述の C エントリポイントをエクスポートすれば、C、C++、Zig、Rust でサービスを実装できます。サービスは JSON で Go ラッパーと通信し、新しい UI プリミティブは追加しません。

拡張のリリースバージョンは、マニフェスト、npm パッケージ、`RequireExtension` の呼び出しで揃えてください。

## 依存関係の宣言

インポートする Go パッケージの隣に `quickgui.extension.json` を置きます。

```json
{
  "schema": 1,
  "name": "acme-echo",
  "abi": 1,
  "package": "@acme/extension-echo",
  "version": "1.0.0",
  "library": "quickgui_acme_echo"
}
```

名前は小文字で始まり、数字とハイフンを含められます。`host` は予約されています。`library` フィールドは `quickgui_` に、ハイフンをアンダースコアへ変えた名前を続けたものです。

要件を登録し、パッケージ内で呼び出しをラップします。

```go
package echo

import (
	"encoding/json"

	"github.com/egoist/quickgui/go/host"
	"github.com/egoist/quickgui/go/native"
)

func init() {
	host.RequireExtension("acme-echo", "1.0.0")
}

func Send(message string, done func(string, error)) {
	native.InvokeExtension("acme-echo", "echo", message, func(raw string, err error) {
		var reply string
		if err == nil {
			err = json.Unmarshal([]byte(raw), &reply)
		}
		done(reply, err)
	})
}
```

`init` でウィンドウを開いたりワーカーを起動したりしないでください。操作は `native.Run` の準備後に呼び出します。応答は UI ゴルーチンで実行されます。

長寿命のサービスでは `native.OpenExtension(name, options, changed, ready)` がセッションを返します。JSON の結果には `session.Request`、成功またはエラーだけでよい場合は `session.Command` を使います。オーナーがなくなったらセッションを閉じてください。

CLI が同梱するにはパッケージのインポートで十分です。マニフェストと `RequireExtension` の両方が必要です。

## ネイティブインターフェースを実装する

ネイティブライブラリから `quickgui_extension_v1` をエクスポートします。名前、バージョン、`invoke` と `shutdown` の 2 つの関数を持つディスクリプターを返します。リクエストのバイト列は保持する前にコピーし、遅い処理はワーカーで行い、JSON で応答します。

よくあるリクエストは次のとおりです。

| リクエスト | 使うとき |
| --- | --- |
| `echo` のようなメソッド | 単発の `InvokeExtension` |
| `start` | `OpenExtension` がセッションを開いたとき |
| `send` のようなコマンド | そのセッション上の処理 |
| `stop` | セッションが閉じるとき |
| `shutdown` | アプリが終了するとき |

リクエストごとに 1 回だけ応答します。セッションを閉じたら、その後のイベントは止めてください。単発サービスの全体は [C の echo 例](https://github.com/egoist/quickgui/blob/main/examples/native-extension/backend/echo.c) を参照してください。

## 自動登録

アプリ起動時、同梱された各拡張は名前とバージョンで読み込まれます。選択するのはパッケージのインポートです。同じ名前でバージョンが衝突すると起動に失敗します。

## 成果物のビルドとパッケージ化

対応する各 OS とアーキテクチャでネイティブライブラリをビルドし、`artifacts/lib/<target>/` に置きます。ターゲットディレクトリは `darwin-arm64`、`darwin-x64`、`linux-arm64`、`linux-x64`、`windows-arm64`、`windows-x64` です。

成果物は npm パッケージとして公開します。

```json
{
  "name": "@acme/extension-echo",
  "version": "1.0.0",
  "files": ["lib", "README.md"]
}
```

ヘルパー実行ファイルや追加ファイルが必要な場合は、マニフェストの `resources` オブジェクトに `darwin`、`linux`、`windows` 向けの名前を列挙し、それらのファイルをライブラリの隣に置きます。

## テストと配布

利用側アプリで `go get` により Go モジュールを追加し、パッケージをインポートして `bun run dev` または `bun run build` を実行します。ローカルのネイティブバイナリには `QUICKGUI_EXTENSION_DIR` を成果物ディレクトリに設定します。

公開前に次を確認してください。

- パッケージをインポートしないアプリには同梱されないこと。
- ライブラリ不足やバージョン不一致は明確に失敗すること。
- セッションのクローズやアプリ終了でコールバックとワーカーが止まること。
- npm アーカイブをパックし、新しいアプリにインストールして、配布する各ターゲットでそのアプリを実行すること。

エンドユーザーが受け取るのはパッケージ済みアプリケーションです。実行に Bun、Go、ネイティブツールチェーンは不要です。
