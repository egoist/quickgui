自動更新を同梱するには `github.com/egoist/quickgui/go/updater` をインポートします。インポートしないアプリにはアップデーターは含まれません。

## 設定

Ed25519 のキーペアを生成します。

```sh
bunx @quickgui/cli keygen --sparkle --out-dir /secure/my-app-update-keys
```

秘密鍵の `.key` はバージョン管理に含めないでください。`.pub` の内容を `quickgui.toml` にコピーします。

```toml
[updates]
baseUrl = "https://downloads.example.com/my-app"
publicKey = "BASE64_PUBLIC_KEY_FROM_THE_PUB_FILE"
automaticChecks = true
# Optional; {target} expands to darwin-arm64, windows-x64, and so on.
feedUrl = "https://downloads.example.com/my-app/appcast-{target}.xml"
# Optional release notes, at most 16 KiB of plain text.
notesFile = "RELEASE_NOTES.md"
```

CLI はバージョン、`identifier`、feed URL、公開鍵をアプリに埋め込みます。秘密鍵は埋め込みません。

Developer ID アプリに対応しています。App Store およびサンドボックスのビルドでは、Go のビルドタグまたはプラットフォーム固有ファイルで updater のインポートを除外してください。

## アプリでの使用

アップデーターは `native.Run` の準備ができたあと、コンポーネントの外で開始します。設定、メニュー、更新バナーで 1 つのハンドルを共有します。ウィンドウを閉じてもアップデーターは閉じないでください。

```go
import (
	"log"

	"github.com/egoist/quickgui/go/native"
	"github.com/egoist/quickgui/go/updater"
)

var updates *updater.Updater

func startUpdater() {
	updates = updater.Start(updater.Options{}, func(event updater.Event) {
		if event.Error != "" {
			log.Print(event.Error)
		}
		if event.QuitRequired {
			native.App.Quit(false, nil)
		}
	}, func(err error) {
		if err != nil {
			log.Print(err)
		}
	})
}
```

「更新を確認」メニューからは `updates.Check(done)`、更新ありのバナーからは `updates.Install(done)`、設定からは `updates.SetAutomaticChecks(enabled, done)` を呼び出します。コールバックは UI ゴルーチンで実行されます。`State()` は最後のイベントを返します。

`Options` で feed URL と公開鍵を上書きできます。開発ビルドは、テスト用 feed と破棄可能なアプリバンドルに対して `AllowDevelopment: true` を設定しない限り無効のままです。

## ライフサイクル

`Event.Status` は `idle`、`checking`、`available`、`downloading`、`installing`、`disabled` のいずれかです。イベントにはバージョン、説明、進捗、自動確認の設定、任意のエラーが含まれます。

macOS では Sparkle がダウンロード、検証、インストール、再起動を担当します。定期確認の結果はアプリ内バナーに渡せます。手動確認では Sparkle の標準ウィンドウを表示できます。

Windows と Linux では、自動確認がオンのとき起動ごとに 1 回確認します。`QuitRequired` はインストーラーの準備完了を意味します。未保存の作業を処理したあと `native.App.Quit(false, nil)` を呼び出してください。終了がキャンセルされた場合、ヘルパーは 2 分待機し、実行中のアプリはそのまま残します。

## 対応プラットフォーム

| プラットフォーム | 更新のペイロード | インストール |
| --- | --- | --- |
| macOS | 署名済み `.app` を含む ZIP | Sparkle |
| Windows | QuickGUI の NSIS `.exe` インストーラー | ヘルパーが終了を待ち、インストーラーをサイレント実行してから再起動します |
| Linux | Type-2 の `.AppImage` | ヘルパーが終了を待ち、ユーザー所有の AppImage を置換します |

Linux の `.deb` パッケージ、システムバイナリ、root 所有のインストールは `disabled` を報告します。パッケージマネージャーを使ってください。

feed は Ed25519 署名付きの HTTPS Sparkle appcast です。アーキテクチャごとに feed が分かれます。差分更新と段階的ロールアウトは生成されません。

## 更新の公開

秘密鍵は `QUICKGUI_UPDATER_PRIVATE_KEY`（または `SPARKLE_PRIVATE_KEY`）に置きます。ローカル署名では `updates.ed25519SecretKey` で鍵ファイルを指定できます。

```sh
bunx @quickgui/cli build --update-manifest
```

CLI はプラットフォームの成果物に署名し、`appcast-<target>.xml` を書き出します。バージョン付き成果物を先にアップロードし、その後 HTTPS URL の feed を置き換えてください。`updates.manifest = true` にすると、本番ビルドのたびに feed が生成されます。

macOS のアーカイブには Developer ID 署名と公証済みのアプリを含めてください。Windows には `makensis` が必要です。Linux で更新可能な AppImage にするには `appimagetool` が必要です。

[updater の例](https://github.com/egoist/quickgui/tree/main/examples/updater) と [Sparkle のドキュメント](https://sparkle-project.org/documentation/) を参照してください。

## ネイティブ成果物

アプリがパッケージをインポートしていれば、本番ビルドにはアップデーターがすでに含まれます。エンドユーザーはパッケージ済みアプリを実行するだけで、追加のアップデーター用ツールは不要です。
