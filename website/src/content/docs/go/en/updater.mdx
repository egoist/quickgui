Import `github.com/egoist/quickgui/extensions/updater` to include automatic updates. Apps that do not import it do not ship the updater.

## Configuration

Generate a signing key pair:

```sh
quickgui keygen --sparkle --out-dir /secure/my-app-update-keys
```

Keep the private `.key` out of version control. Copy the `.pub` contents into config:

```toml
[updates]
baseUrl = "https://downloads.example.com/my-app"
publicKey = "BASE64_PUBLIC_KEY_FROM_THE_PUB_FILE"
automaticChecks = true
feedUrl = "https://downloads.example.com/my-app/appcast-{target}.xml"
notesFile = "RELEASE_NOTES.md"
```

`{target}` expands to values such as `darwin-arm64`. Release notes are optional plain text, up to 16 KiB.

The CLI embeds the version, identifier, feed URL, and public key. Secret keys are never embedded. App Store and sandboxed builds should exclude the updater import with a Go build tag.

## Application usage

Start after `native.Run` is ready, outside components. Share one updater for the whole app.

```go
import (
	"log"

	"github.com/egoist/quickgui/go/native"
	"github.com/egoist/quickgui/extensions/updater"
)

var updates *updater.Updater

func startUpdater() {
	updates = updater.Start(updater.Options{}, func(event updater.Event) {
		if event.Error != "" {
			log.Print(event.Error)
		}
		if event.QuitRequired {
			native.App.Quit(false, nil)
		}
	}, func(err error) {
		if err != nil {
			log.Print(err)
		}
	})
}
```

Call `updates.Check(done)` from a Check for Updates item, `updates.Install(done)` from an available-update banner, and `updates.SetAutomaticChecks(enabled, done)` from settings. Callbacks run on the UI goroutine. `State()` returns the latest event.

`Options` can override the feed URL and public key. Development builds are disabled by default. Use `AllowDevelopment: true` only with a test feed and a disposable app bundle.

## Lifecycle

`Event.Status` is `idle`, `checking`, `available`, `downloading`, `installing`, or `disabled`. Events include version, notes, progress, the automatic-check preference, and an optional error.

On macOS, Sparkle handles download, verification, installation, and relaunch. Manual checks can show Sparkle’s standard UI; scheduled checks can feed an in-app banner.

Windows and Linux check once at launch when automatic checking is enabled. `QuitRequired` means a helper is waiting for the app to exit. Call `native.App.Quit(false, nil)` after saving work. If quit is cancelled, the helper times out and leaves the current app in place.

## Platforms

| Platform | Update payload | Installation |
| --- | --- | --- |
| macOS | ZIP containing the signed `.app` | Sparkle, included only with the updater |
| Windows | NSIS `.exe` installer | A helper waits for exit, runs the verified installer silently, then relaunches |
| Linux | Type-2 `.AppImage` | A helper waits for exit and replaces the user-owned AppImage |

Linux `.deb` packages, system binaries, and root-owned installs report `disabled`. Use the platform package manager there.

Feeds are HTTPS Sparkle RSS appcasts with Ed25519 signatures. There is no unsigned fallback.

## Publishing

Put the private key in `QUICKGUI_UPDATER_PRIVATE_KEY` (or `SPARKLE_PRIVATE_KEY`). Alternatively, `updates.ed25519SecretKey` points to a local key file.

```sh
quickgui build --update-manifest
```

The CLI signs the artifact and writes `appcast-<target>.xml`. Upload the versioned artifact first, then replace the feed. Each architecture has its own feed. `updates.manifest = true` generates a feed on every production build.

macOS archives should contain a Developer ID signed, notarized app. Windows needs `makensis`. Linux needs `appimagetool`.

## Native artifacts

From this repository, build the updater once with `bun packages/native/build.ts --extension updater`. Packaged apps include the updater automatically when the Go import is present.

See the [updater example](https://github.com/egoist/quickgui/tree/main/examples/updater). Sparkle’s own docs cover appcast details: [Sparkle](https://sparkle-project.org/documentation/).
